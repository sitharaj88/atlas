> **What you'll learn.** The three variable keywords and when each one applies. The "hoisting" question that comes up in every interview, and what the **temporal dead zone** is.

## The three keywords

```js
const name = 'Atlas';   // can't be reassigned
let count = 0;          // can be reassigned
var legacy = 'avoid';   // function-scoped; surprises
```

**Default to `const`.** Use `let` when you need to reassign. Don't use `var`.

## Const doesn't mean immutable

`const` prevents **reassignment** of the binding, not mutation of the value:

```js
const list = [];
list.push(1);          // ✓ mutating; not reassigning
list = [1, 2];         // ✗ TypeError — reassignment
```

For real immutability use `Object.freeze(obj)` or a library like Immer.

## Block scope vs. function scope

`let` and `const` are **block-scoped**: they live inside the nearest `{}`.

```js
if (true) {
  const x = 1;
}
console.log(x); // ReferenceError — not defined here
```

`var` is **function-scoped** (or global if outside any function):

```js
function f() {
  if (true) { var x = 1; }
  console.log(x); // 1 — `var` ignores the if-block
}
```

## Hoisting

JS engines, before running a function/block, scan it and "hoist" declarations to the top:

```js
console.log(x);   // undefined  (var x is hoisted as `undefined`)
var x = 5;

console.log(y);   // ReferenceError (let exists but unaccessible)
let y = 5;

f();              // ✓ works — function declarations are fully hoisted
function f() {}

g();              // TypeError — g is undefined here
var g = function() {};
```

`function` declarations are hoisted with their bodies. `var` declarations are hoisted but initialized to `undefined`. `let`/`const` are hoisted but **not initialized** — accessing them before the declaration throws.

## The temporal dead zone (TDZ)

The window between entering a block and reaching a `let`/`const` declaration:

```js
{
  console.log(name);   // ReferenceError — TDZ
  let name = 'Atlas';
}
```

This is by design — it surfaces bugs that `var` would silently allow.

<Callout variant="tip" title="Just declare at the top">
The simplest rule: declare variables before you use them, in roughly the order of use. TDZ becomes invisible. Modern linters flag use-before-declaration so you don\'t even have to remember.
</Callout>

## Closures (preview)

A function "closes over" the variables in scope when it was defined:

```js
function counter() {
  let n = 0;
  return () => ++n;
}
const next = counter();
next(); // 1
next(); // 2
```

The inner arrow function still has access to `n`, even though `counter()` has returned. This is how event handlers, timeouts, and React hooks all carry data forward.
