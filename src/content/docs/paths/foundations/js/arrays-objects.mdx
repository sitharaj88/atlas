> **What you'll learn.** How to manipulate arrays and objects in modern JS — including the immutable methods that make state updates safe in React, Redux, and friends.

## Arrays — the methods you'll use 100× a week

```js
const xs = [1, 2, 3, 4];

xs.map(x => x * 2);              // [2, 4, 6, 8]
xs.filter(x => x % 2 === 0);     // [2, 4]
xs.find(x => x > 2);             // 3
xs.findIndex(x => x > 2);        // 2
xs.some(x => x > 3);             // true
xs.every(x => x > 0);            // true
xs.includes(3);                  // true
xs.reduce((acc, x) => acc + x, 0); // 10

xs.indexOf(3);                   // 2
xs.lastIndexOf(3);               // 2
xs.slice(1, 3);                  // [2, 3]   — copy a range
xs.concat([5, 6]);               // [1, 2, 3, 4, 5, 6]
xs.join(', ');                   // "1, 2, 3, 4"
[...new Set([1, 2, 2, 3])];      // [1, 2, 3]  — dedupe via Set
```

## Mutators (use with care)

```js
xs.push(5);            // append, returns new length
xs.pop();              // remove last, returns it
xs.shift();            // remove first
xs.unshift(0);         // prepend
xs.splice(1, 2, 'a');  // remove 2 starting at index 1, insert 'a'
xs.sort();             // in-place
xs.reverse();          // in-place
```

These mutate the original. In modern code (React, etc.) you usually want immutable variants:

## The immutable methods (ES2023+)

```js
xs.toSorted((a, b) => a - b);  // returns a NEW sorted copy
xs.toReversed();
xs.toSpliced(1, 2, 'a');
xs.with(0, 99);                // returns a copy with index 0 replaced
```

Use these in React state updates. No more `[...xs].sort(...)` ceremony.

## Spread, destructuring, defaults

```js
const xs = [1, 2, 3];
const ys = [...xs, 4, 5];      // copy + append
const [first, ...rest] = xs;   // first = 1, rest = [2, 3]
const [a, b = 10] = [1];       // a = 1, b = 10 (default)

const obj = { name: 'Ada', age: 36 };
const copy = { ...obj };
const merged = { ...obj, age: 37 };  // age wins from later spread
const { name, age, role = 'user' } = obj;
```

## Object methods

```js
Object.keys(obj);    // ['name', 'age']
Object.values(obj);  // ['Ada', 36]
Object.entries(obj); // [['name', 'Ada'], ['age', 36]]
Object.fromEntries([['a', 1], ['b', 2]]); // { a: 1, b: 2 }

Object.freeze(obj);  // shallow immutability
Object.assign({}, a, b); // shallow merge — but { ...a, ...b } is cleaner

Object.hasOwn(obj, 'name'); // safer than obj.hasOwnProperty
```

The combo `Object.entries → map → Object.fromEntries` is a tiny pipeline for transforming objects:

```js
const upper = Object.fromEntries(
  Object.entries(obj).map(([k, v]) => [k, String(v).toUpperCase()])
);
```

## Map and Set — when objects aren't enough

```js
// Map: keys can be ANY value (objects too); preserves insertion order
const m = new Map();
m.set('a', 1);
m.get('a');     // 1
m.has('a');     // true
m.size;         // 1
[...m];         // [['a', 1]]

// Set: unique values, preserves insertion order
const s = new Set([1, 1, 2]);
s.add(3);
s.has(2);       // true
s.size;         // 3
```

When the key is a string and you want simple property access, plain objects win. When you need any-typed keys, frequent insert/delete, or size tracking, use Map.

## Shallow vs. deep

Spread and `Object.assign` are **shallow** — nested objects share references:

```js
const a = { name: 'Ada', addr: { city: 'NYC' } };
const b = { ...a };
b.addr.city = 'LA';
a.addr.city; // 'LA' — they share the same addr object!
```

For deep clones use `structuredClone(obj)`:

```js
const b = structuredClone(a); // deep copy, including Maps/Sets/Dates
```

`JSON.parse(JSON.stringify(x))` works for plain JSON-safe data only. `structuredClone` handles more types.

<Callout variant="tip" title="Update React state immutably">
React compares by reference. If you mutate state in place, React doesn\'t re-render. Always use spread or the new `to-` array methods for updates.
</Callout>
