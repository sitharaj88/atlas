> **What you'll learn.** Three eras of async JS: the callback era (hard), the Promise era (better), and the async/await era (where we live now). All three still appear in real code.

## The callback era

```js
fs.readFile('a.txt', (err, a) => {
  if (err) return done(err);
  fs.readFile('b.txt', (err, b) => {
    if (err) return done(err);
    fs.readFile('c.txt', (err, c) => {
      if (err) return done(err);
      done(null, a + b + c);
    });
  });
});
```

This is "callback hell." Errors propagate manually. Branching gets messy. Modern code avoids this — but you'll meet it in old libraries.

## Promises

A **Promise** is an object that represents a future value. It's in one of three states:

- **Pending** — not yet settled.
- **Fulfilled** — completed successfully, has a value.
- **Rejected** — failed, has an error.

```js
const p = fetch('/api');
p.then(res => res.json())
 .then(data => console.log(data))
 .catch(err => console.error(err))
 .finally(() => console.log('done'));
```

A Promise can settle exactly once. Once settled, it stays settled.

## Creating a Promise

You almost never write `new Promise` directly — you call APIs that return Promises. But when wrapping a callback API:

```js
function readFile(path) {
  return new Promise((resolve, reject) => {
    fs.readFile(path, (err, data) => {
      if (err) reject(err);
      else resolve(data);
    });
  });
}
```

`util.promisify(fs.readFile)` (in Node) does this automatically.

## async / await

Syntactic sugar over Promises:

```js
async function loadAll() {
  try {
    const a = await readFile('a.txt');
    const b = await readFile('b.txt');
    const c = await readFile('c.txt');
    return a + b + c;
  } catch (err) {
    console.error(err);
  }
}
```

Reads top-to-bottom, error handling is `try/catch`. `await` only works inside `async` functions (and at module top level).

**Every async function returns a Promise.** Calling `loadAll()` gives you a Promise that resolves with `a + b + c`.

## Sequential vs. parallel

The above runs sequentially — one file at a time. To go in parallel:

```js
const [a, b, c] = await Promise.all([
  readFile('a.txt'),
  readFile('b.txt'),
  readFile('c.txt'),
]);
```

`Promise.all` rejects fast if any input rejects. Use **`Promise.allSettled`** when you want every result, success or failure.

## The combinators

```js
Promise.all([p1, p2, p3])         // resolves with array; rejects if any reject
Promise.allSettled([p1, p2, p3])  // resolves with array of {status, value/reason}
Promise.race([p1, p2, p3])        // resolves/rejects with the FIRST to settle
Promise.any([p1, p2, p3])         // resolves with the first to FULFILL; rejects only if all reject
```

`Promise.any` is great for "try several services, take whichever responds first."

## await is one expression

You can `await` anywhere an expression is allowed:

```js
const total = (await fetchA()) + (await fetchB());
const items = (await fetch('/api/items')).map(transform);
const ok = list.some(async (x) => await check(x)); // ❌ this is wrong! .some passes a function; await inside doesn't help
```

The last one is a classic trap. Array methods like `.some`, `.every`, `.filter` don't await. Use `for…of` or `Promise.all(list.map(...))`.

## Top-level await

In ES modules:

```js
// data.js (an ES module)
export const data = await fetch('/api/data').then(r => r.json());
```

Modules that use top-level await delay their importers. Use sparingly; it can serialize startup.

## Common pitfalls

```js
// ❌ Forgetting await — Promise leaks through
async function getData() {
  return fetch('/api').then(r => r.json()); // works (return is implicit await on return)
}

// ❌ Awaiting in a forEach
arr.forEach(async (x) => await process(x)); // does NOT wait — forEach ignores the returned Promise

// ✓ Await with for…of (sequential)
for (const x of arr) await process(x);

// ✓ Await with Promise.all (parallel)
await Promise.all(arr.map(process));
```

<Callout variant="tip" title="Convert callbacks to Promises early">
Whenever you start to nest more than two callbacks, stop and wrap them in `new Promise` (or use `util.promisify`). Linear async/await code is easier to read and easier to debug.
</Callout>
