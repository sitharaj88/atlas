## Where to put them

GitHub: Settings → Secrets and variables → Actions:

- **Repository secrets** — available to all workflows in the repo.
- **Environment secrets** — scoped to deploy environments (with required approvals).
- **Organization secrets** — shared across many repos.

## Use them

```yaml
- run: deploy.sh
  env:
    DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}
```

GitHub masks any string matching a secret value in logs.

## Where they leak

- **`echo $SECRET`** — masked in logs but appears in CI output formatters that don't know about the masking.
- **Forking PRs** that run on secrets-having workflows — never run untrusted PRs against secrets. Use `pull_request_target` carefully.
- **Build artifacts** that include `.env` files. Never upload them.
- **Cached node_modules** — packages can read env vars at install time. Pin versions, audit.

## OIDC > long-lived secrets

GitHub can mint short-lived tokens for AWS/GCP/Azure deploys via OIDC:

```yaml
permissions: { id-token: write, contents: read }
- uses: aws-actions/configure-aws-credentials@v4
  with: { role-to-assume: arn:aws:iam::1234:role/deployer, aws-region: us-east-1 }
```

No long-lived AWS keys to leak.
