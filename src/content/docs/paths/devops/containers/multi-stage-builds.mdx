## The pattern

```dockerfile
# 1. Build stage — has all build tools
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

# 2. Production stage — minimal runtime
FROM node:20-alpine
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --prod --frozen-lockfile
COPY --from=build /app/dist ./dist
CMD ["node", "dist/server.js"]
```

The final image has only the production dependencies and the built output. No `pnpm`, no source files, no dev tools. Often 5–10× smaller than a single-stage build.

## Distroless (even smaller)

```dockerfile
FROM gcr.io/distroless/nodejs20
COPY --from=build /app/dist ./dist
CMD ["dist/server.js"]
```

No shell, no package manager — just node + your app. Smaller attack surface, harder to exec into for debugging.
