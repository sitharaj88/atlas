## Trunk-based

One main branch (`main`). Short-lived feature branches merge frequently. Releases via tags or feature flags.

Pros: fast iteration, fewer merge conflicts, CI/CD friendly.

Cons: needs feature flags to ship safely.

## GitFlow

`main` (releases), `develop` (next release), `feature/*`, `release/*`, `hotfix/*` branches.

Pros: explicit release cycle, fits regulated industries.

Cons: complex, slower, conflicts pile up.

## What most teams should pick

**Trunk-based** unless you have a reason. Most companies do continuous delivery; GitFlow's structure becomes overhead.

For greenfield projects: short-lived branches, daily merges, feature flags for partial rollouts.
