## What TDD is

Red → Green → Refactor.

1. Write a failing test.
2. Write the minimum code to pass.
3. Refactor without breaking the test.

## When it shines

- **Pure logic** — parsers, calculators, schedulers. Cheap to test, expensive to debug.
- **Bug fixes** — write a test that reproduces the bug, then fix.
- **Hard refactors** — wrap in tests first, refactor with safety net.

## When it gets in the way

- **UI exploration.** When you don't know what the design should be, tests slow iteration.
- **Throwaway prototypes.**
- **Spike work** — proving a concept.

## Hybrid in practice

Most pros write tests:
- **First** for new pure logic.
- **After** the design settles for UI.
- **Always** for regressions (test = bug ticket).
