## The classic pyramid

```text
  /\          E2E       (few, slow, real)
 /  \         ↕
/____\        Integration (some, medium)
        Unit       (many, fast, isolated)
```

Many fast tests, few slow ones.

## The Testing Trophy (Kent C. Dodds)

For frontend, integration tests provide the best ROI:

```text
  E2E           (few)
  Integration   (most)
  Unit          (some)
  Static        (TS, ESLint — free)
```

Component tests using Testing Library are integration tests — they exercise multiple units together, give high confidence, and run fast.

## When to write what

- **Unit** — pure logic. Algorithms, parsers, formatters.
- **Component** — UI behavior. Renders, clicks, accessibility.
- **E2E** — critical user flows. Login, checkout, signup.
- **Visual regression** — design didn't drift.
