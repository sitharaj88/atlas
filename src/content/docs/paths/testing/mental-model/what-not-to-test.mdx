## Don't test implementation details

```ts
// ❌ Tests the internal state shape
expect(wrapper.state().count).toBe(1);

// ✓ Tests the user-visible outcome
expect(screen.getByRole('status')).toHaveTextContent('1');
```

Tests should break when **behavior** breaks, not when **structure** is refactored.

## Smells

- **Mocking your own code.** If you mock half your modules, you're testing the mocks, not your code.
- **Snapshots that nobody reads.** A pile of "matches snapshot" tests rot quickly.
- **Tests that check method calls** (`expect(spy).toHaveBeenCalled`). Behavior, not invocation, is what users see.
- **100% coverage as a goal.** Coverage measures lines hit, not behavior verified. 80% with high-quality tests beats 100% with tautologies.

## The right question

Before writing a test, ask: **"What user-visible thing breaks if this isn't true?"** If you can answer that, write the test. Otherwise skip.
