## The hierarchy

Testing Library queries, ordered by preference:

1. **`getByRole`** — what assistive tech sees. `getByRole('button', { name: 'Submit' })`.
2. **`getByLabelText`** — for form fields.
3. **`getByPlaceholderText`** — when no label.
4. **`getByText`** — for non-interactive content.
5. **`getByDisplayValue`** — for filled-in form fields.
6. **`getByAltText`** — for images.
7. **`getByTitle`** — last resort for visual elements.
8. **`getByTestId`** — when nothing else works. Add `data-testid`.

## Why role-based

If `getByRole('button')` finds your button, screen readers can too. Tests double as a11y check.

## Variants

- **`getBy...`** — throws if missing (one element).
- **`queryBy...`** — returns null if missing.
- **`findBy...`** — async, waits.
- **`getAllBy...` / `findAllBy...`** — multiple matches.

## A sample component test

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';

it('shows hello after click', async () => {
  render(<Greeter />);
  await userEvent.click(screen.getByRole('button', { name: /say hi/i }));
  expect(await screen.findByRole('status')).toHaveTextContent('Hello!');
});
```
