## Why MSW

Mocking `fetch` is OK for unit tests. For integration tests, MSW intercepts at the network layer — your code runs unchanged, the response comes from your handler.

## Setup

```ts
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';

const server = setupServer(
  http.get('/api/users/:id', ({ params }) => {
    return HttpResponse.json({ id: params.id, name: 'Ada' });
  }),
);

beforeAll(() => server.listen());
afterEach(() => server.resetHandlers());
afterAll(() => server.close());
```

In the browser, MSW uses a real Service Worker. In Node tests, it patches `fetch`.

## In Storybook

Use the same handlers in Storybook, dev, and tests. One source of truth for stubs.

## Test errors

```ts
it('shows error on 500', async () => {
  server.use(http.get('/api/users/:id', () => HttpResponse.error()));
  render(<UserPage />);
  expect(await screen.findByText(/something went wrong/i)).toBeInTheDocument();
});
```
