## What it measures

When the largest visible image/text/video element finished rendering. Goal: ≤ 2.5s at the 75th percentile.

## Common causes

- LCP image discovered late (deep in the HTML or via JS).
- Server slow to send the first byte (TTFB).
- Render-blocking CSS / JS in head.
- Web font that swaps in late.

## Fixes

```html
<!-- Hint the browser early -->
<link rel="preload" as="image" href="/hero.avif" fetchpriority="high">

<!-- LCP image: high priority and not lazy -->
<img src="/hero.avif" alt="..." fetchpriority="high" decoding="async">

<!-- Inline above-the-fold CSS -->
<style>/* critical */</style>

<!-- Font that doesn't block text -->
@font-face { font-display: swap; }
```

`fetchpriority="high"` is the single biggest win for LCP images.

## Verify

DevTools → Performance → Run → look for the LCP marker. Hover to see the LCP element. Check whether it was render-blocked or network-blocked.
