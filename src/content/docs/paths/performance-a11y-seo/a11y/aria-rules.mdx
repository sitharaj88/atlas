## The five rules

1. **Don't use ARIA if HTML can do it.**
2. **Don't change native semantics.** `<a role="button">` is wrong.
3. **All interactive ARIA controls must be keyboard accessible.** Including `tabindex="0"`, Space, Enter.
4. **Don't make focusable elements `aria-hidden="true"`.** And don't use `role="presentation"` on focusable elements.
5. **All interactive controls must have an accessible name.** Visible text, `aria-label`, or `aria-labelledby`.

## The most-useful attributes

- **`aria-label`** — accessible name when there's no visible text.
- **`aria-labelledby`** — point at another element's text.
- **`aria-describedby`** — extra description.
- **`aria-live="polite"`** — announce dynamic changes.
- **`aria-expanded`** — toggle / disclosure state.

## Common mistakes

- Adding ARIA to native elements that already have the role.
- `role="button"` on a `<div>` without keyboard handlers.
- `aria-hidden="true"` on a focusable button (focus + can't read = bug).
- Conflicting visible text and `aria-label`.
