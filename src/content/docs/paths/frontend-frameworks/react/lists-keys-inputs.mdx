## Keys

```jsx
{items.map(i => <Item key={i.id} {...i} />)}
```

Keys help React match elements between renders. **Always use a stable, unique ID** — the database id, a slug, a UUID. Never the array index unless the list never reorders.

Bad keys cause:
- State leaking between items (focus, internal state).
- Re-renders that should have been no-ops.
- Animations that confuse "old" and "new" items.

## Controlled inputs

State lives in React; input shows it:

```jsx
const [name, setName] = useState('');
return <input value={name} onChange={e => setName(e.target.value)} />;
```

Pros: full control, validation while typing, derived state. Cons: every keystroke re-renders.

## Uncontrolled inputs

State lives in the DOM; React reads it on submit:

```jsx
const ref = useRef();
return <input ref={ref} defaultValue="" />;
// later: ref.current.value
```

Pros: no per-keystroke render. Cons: harder to validate live.

For most forms in React 19+, **controlled** is fine. Performance is rarely the bottleneck. Reach for uncontrolled (or `useFormStatus`) when typing feels laggy.
