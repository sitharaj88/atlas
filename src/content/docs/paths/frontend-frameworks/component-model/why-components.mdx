## Imperative DOM

```js
const list = document.getElementById('list');
list.innerHTML = '';
for (const item of items) {
  const li = document.createElement('li');
  li.textContent = item.name;
  list.append(li);
}
```

You tell the browser **what to do**, step by step. Easy at small scale; nightmare at any scale.

## Declarative components

```jsx
function List({ items }) {
  return <ul>{items.map(i => <li key={i.id}>{i.name}</li>)}</ul>;
}
```

You describe **what the UI should look like for this state**. The framework figures out the DOM operations.

When `items` changes, you don't update DOM — you re-run the function. The framework reconciles the result with what's already on screen.

## The big win

The mental load drops by an order of magnitude. You think about *data*; the framework handles the DOM.
