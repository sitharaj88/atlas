## The model

Astro renders to static HTML. Components are server-rendered by default — no JS shipped. You opt into hydration on a per-component basis (an "island"):

```astro
---
import Counter from './Counter.tsx';
---
<h1>Welcome</h1>
<Counter client:visible />
```

`client:load`, `client:idle`, `client:visible`, `client:media` — different hydration triggers. Most components stay static.

## When Astro shines

- Documentation sites (this very Atlas runs on Starlight, which is Astro).
- Marketing sites.
- Blogs.
- Anywhere content is the product.

## When Astro doesn't fit

- Highly interactive apps (dashboards, editors). Reach for Next/Remix/SvelteKit instead.
- Realtime/collaborative features. Astro can do them via islands but it's not the sweet spot.
