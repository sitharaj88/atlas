## What you get

- File-based routing (App Router).
- React Server Components + Server Actions out of the box.
- Image, font, and script optimization.
- Edge & Node runtime selection per route.
- Middleware, route handlers, streaming.
- First-class Vercel deploy; runs anywhere as a Node server.

## App Router shape

```
app/
├── layout.tsx        # root layout
├── page.tsx          # /
├── posts/
│   ├── page.tsx      # /posts
│   └── [id]/
│       └── page.tsx  # /posts/:id
└── api/route.ts      # /api (route handler)
```

`page.tsx` is the route. `layout.tsx` wraps. Components are server by default — add `'use client'` when interactive.

## Server Components fetch directly

```tsx
export default async function Posts() {
  const posts = await db.post.findMany();
  return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}
```

No useEffect, no client-side fetch — just `await`.

## When Next is the right pick

- You want server components, server actions, file-based routing — all in one default.
- You're deploying to Vercel (or comfortable with their patterns elsewhere).
- You want the largest community and library ecosystem.

## When to look elsewhere

- You want a non-React stack.
- You want a smaller, more transparent framework (Astro for content, TanStack Start for client-heavy).
- You really don't want Vercel-flavored choices.
