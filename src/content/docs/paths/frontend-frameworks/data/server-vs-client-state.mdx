## The two kinds

**Client state** — UI state owned by your app: form input, "is the modal open," theme. Lives in `useState`/Zustand/Context.

**Server state** — data owned by a server, cached locally: lists of posts, user profiles. Asynchronous, can become stale, can be refetched. Needs caching, dedup, retries, refetch-on-focus.

Trying to handle server state with `useState` (`useState` + `useEffect` + `loading`/`error`/`data`) reinvents poorly what TanStack Query does well.

## TanStack Query

```jsx
const { data, isLoading, error } = useQuery({
  queryKey: ['posts'],
  queryFn: () => fetch('/api/posts').then(r => r.json()),
});
```

You get for free:
- Caching keyed by `queryKey`.
- Refetching on focus, on network reconnect, on stale.
- Dedup — multiple components asking the same key share one request.
- Mutations with cache invalidation.

For React-based apps, **TanStack Query (or its newer SSR-friendly siblings) is the default for server state.**

## Mutations

```jsx
const mutation = useMutation({
  mutationFn: (post) => fetch('/api/posts', { method: 'POST', body: JSON.stringify(post) }),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['posts'] }),
});
mutation.mutate({ title: 'Hello' });
```
