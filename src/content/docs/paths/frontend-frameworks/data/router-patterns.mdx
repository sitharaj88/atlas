## File-based

Folder structure becomes routes. `app/posts/[id]/page.tsx` → `/posts/:id`. Used by Next.js, Remix/React Router 7, TanStack Start, Astro, SvelteKit.

Pros: convention. Easy to find the file for a route. Routing config is implicit.

Cons: nesting and dynamic segments require care. Editor refactors don't always understand routes.

## Code-first

Routes are JS data:

```js
const routes = [
  { path: '/', element: <Home /> },
  { path: '/posts/:id', element: <Post /> },
];
```

Used by older React Router, Solid Router (option), Vue Router.

Pros: explicit. Easy to share, transform, generate.

Cons: more boilerplate. The bigger the app, the more painful.

## Verdict for new apps

**Use a file-based router** that ships with a meta-framework. The convention is well-trodden, the tooling is excellent, and you avoid hand-maintaining a routes table.
