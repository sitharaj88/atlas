## The architecture

```text
Browser → your server: "Start checkout for product X"
Server → Stripe API: create Checkout Session, get URL
Server → browser: redirect to Stripe-hosted checkout
User pays on stripe.com
Stripe → your server (webhook): "session.completed" — fulfill the order
```

You never touch card numbers. Stripe is PCI-compliant; you don't need to be.

## A Checkout Session

```ts
const session = await stripe.checkout.sessions.create({
  mode: 'payment',
  line_items: [{ price: 'price_abc', quantity: 1 }],
  success_url: 'https://atlas.dev/thanks?session_id={CHECKOUT_SESSION_ID}',
  cancel_url: 'https://atlas.dev/cancelled',
});
return c.redirect(session.url);
```

## Webhooks are the source of truth

The user might close the tab before redirecting back. Always listen for `checkout.session.completed`:

```ts
app.post('/webhook', async (c) => {
  const sig = c.req.header('stripe-signature')!;
  const event = stripe.webhooks.constructEvent(await c.req.text(), sig, secret);
  if (event.type === 'checkout.session.completed') {
    const session = event.data.object;
    await fulfillOrder(session.client_reference_id);
  }
  return c.text('ok');
});
```

Verify the signature. Always. Otherwise anyone can post fake fulfillment events.

## Subscriptions

Same pattern, `mode: 'subscription'`. Listen for `invoice.paid` to extend access; `customer.subscription.deleted` to revoke.
