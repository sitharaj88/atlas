## Use a provider

Don't run an SMTP server. Use:
- **Resend** — modern, dev-friendly, React Email components.
- **Postmark** — strong reputation, transactional focus.
- **SendGrid, Mailgun** — established players.
- **AWS SES** — cheap, requires more setup.

Reputation matters. Sharing a provider's IPs that are already trusted is the fastest path to inbox.

## Authentication records

DNS records that prove your domain is allowed to send:

- **SPF** — list of IPs allowed to send from your domain.
- **DKIM** — cryptographic signature on each message.
- **DMARC** — policy combining SPF + DKIM, reports to you.

Configure all three. Without them, Gmail/Outlook send your mail to spam.

## Transactional vs marketing

- **Transactional** — receipt, password reset, OTP. Triggered by user. Critical to deliver.
- **Marketing** — newsletters, promos. Bulk. Unsubscribe required (CAN-SPAM, GDPR).

Use **separate sending domains** (e.g., `noreply@app.atlas.dev` for transactional, `news@news.atlas.dev` for marketing). A bad marketing reputation won't tank your transactional delivery.

## Building an email

```tsx
// React Email
import { Html, Button } from '@react-email/components';

export default function Welcome({ name }: { name: string }) {
  return (
    <Html>
      <h1>Welcome, {name}</h1>
      <Button href="https://atlas.dev/start">Get started</Button>
    </Html>
  );
}
```

Renders to compatible HTML for old email clients.
