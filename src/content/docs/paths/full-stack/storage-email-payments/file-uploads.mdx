## The wrong way

Browser → your server (multipart) → S3. Doubles the bandwidth bill, blocks server resources.

## The right way

```text
1. Browser → server: "I want to upload `photo.jpg`"
2. Server uses S3 SDK to issue a presigned URL (5 min TTL).
3. Server replies: { uploadUrl, fileKey }.
4. Browser PUTs the file directly to S3 via the presigned URL.
5. Browser → server: "Upload done, key=fileKey"
6. Server validates, stores reference in DB.
```

The big bytes never touch your server.

## Implementation

```ts
// Server (using @aws-sdk/client-s3 + @aws-sdk/s3-request-presigner)
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';
import { PutObjectCommand } from '@aws-sdk/client-s3';

app.post('/api/upload-url', async (c) => {
  const { name, type } = await c.req.json();
  const key = `uploads/${crypto.randomUUID()}/${name}`;
  const url = await getSignedUrl(s3, new PutObjectCommand({
    Bucket: 'my-bucket', Key: key, ContentType: type,
  }), { expiresIn: 300 });
  return c.json({ uploadUrl: url, key });
});
```

Works with **S3, Cloudflare R2, Backblaze B2, MinIO** — all S3-compatible.

## Validation

The browser can lie about file type. After upload:

- Read the first bytes server-side, sniff the actual format.
- Re-encode images server-side (sharp) — strips metadata, normalizes.
- Reject suspicious uploads.
