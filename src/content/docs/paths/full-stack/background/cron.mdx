## Picking a runner

- **GitHub Actions** — cron schedules in YAML. Free for public repos, generous for private.
- **Vercel Cron** — for Vercel-deployed apps. Hits a route on schedule.
- **Cloudflare Triggers** — for Workers.
- **System cron** — on a VPS, classic.
- **In-app schedulers (BullMQ repeat)** — when jobs are tightly coupled to your queue.

## The pitfalls

**Multiple instances run the same job.** Solution: a lock or "leader election" record. The first instance to acquire the lock runs.

```sql
-- Postgres advisory lock
SELECT pg_try_advisory_lock(hash('daily-digest'));
```

**Jobs run forever and overlap.** Solution: a max runtime, killed on timeout. Lock with TTL.

**Time zones.** Always use UTC in cron expressions. Convert for display only.

**Long jobs miss their next run.** Either skip overlapping runs (most common) or queue them with a guard.
