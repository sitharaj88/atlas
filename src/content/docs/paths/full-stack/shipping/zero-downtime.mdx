## The recipe

```text
1. Build new version.
2. Start new instances. Wait for them to pass HEALTH check.
3. Add new instances to load balancer.
4. Drain old instances — stop accepting new requests; finish in-flight.
5. Stop old instances.
```

This is "rolling deploy." Most managed platforms do it for you.

## Health checks

```ts
app.get('/health', (c) => c.json({ ok: true, version: process.env.GIT_SHA }));

app.get('/health/ready', async (c) => {
  await db.execute('SELECT 1');           // can we hit the DB?
  await redis.ping();                      // can we hit Redis?
  return c.json({ ok: true });
});
```

`/health` is for liveness (am I alive?). `/health/ready` is for readiness (can I serve traffic?). Load balancers should use ready.

## Blue-green

Two complete environments. Switch DNS / LB routing from blue to green when green is ready. Roll back instantly by switching back.

Pro: instant rollback. Con: 2x infra cost during switchover.

## Database migrations

Hardest part. The rule:

- **Adding columns** — fine, deploy code that reads optionally.
- **Renaming columns / dropping** — multi-step. Add new column, deploy code that writes both, backfill, deploy code that reads new only, drop old.

Never deploy code that's incompatible with both the old AND new schema simultaneously.
