## Migrations

Schema changes paired with code changes. Run **before** the new code deploys, or interleaved if multi-step.

Tools:
- **Drizzle Kit / Prisma Migrate** — generate from schema diffs.
- **sqlx, Atlas, dbmate** — write SQL by hand.

Always:
- Number migrations sequentially.
- Test in staging.
- Have a rollback plan (or accept that some are forward-only).
- Avoid long-running migrations on big tables in a single transaction.

## Rollbacks

When a deploy goes wrong:

1. **First action: revert.** Don't try to fix forward in production at 2 AM.
2. Most platforms support one-click revert to the previous version.
3. If the migration was destructive, rolling back the code without rolling back the schema is fine — code should tolerate the new schema.
4. Document what went wrong. Improve the runbook.

## Feature flags

Decouple **deploy** from **release**. Code ships; the feature stays off until you flip a flag.

```ts
if (await flags.isEnabled('new-checkout', { userId })) {
  return newCheckout();
} else {
  return oldCheckout();
}
```

Tools: LaunchDarkly, GrowthBook, Unleash, simple Postgres-backed table.

Patterns:
- **Kill switch** — instantly disable a buggy feature.
- **Gradual rollout** — enable for 1%, 10%, 50%, 100%.
- **A/B test** — assign by hash of user ID.
- **Per-user override** — turn on for specific users for testing.
