## The right algorithm

**Argon2id** — current OWASP recommendation. Tunable memory + time cost. Memory-hard (resists GPU brute-force).

```ts
import argon2 from 'argon2';

const hash = await argon2.hash(password, { type: argon2.argon2id });
const valid = await argon2.verify(hash, password);
```

## The wrong choices

- **MD5, SHA1, SHA256** — fast hashes. Too easy to brute-force. Never for passwords.
- **bcrypt** — older but still acceptable. Limited to 72-byte input.
- **PBKDF2** — acceptable, not preferred.
- **scrypt** — fine but tuning is awkward.

## Other rules

- **Salt** is built into Argon2's output. You don't manage it.
- **Pepper** (a server-side secret added before hashing) is optional and adds value if your DB leaks but app secret doesn't.
- **Length**, not complexity, matters. Allow long passwords (up to 128 chars). Don't ban special characters.
- **Compare with constant-time** comparison (Argon2's verify already does this).

## Storage

Schema:

```sql
CREATE TABLE users (
  id        UUID PRIMARY KEY,
  email     TEXT UNIQUE NOT NULL,
  pw_hash   TEXT NOT NULL,    -- Argon2id encoded string
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

Never store plaintext. Never log it. Never email it.
