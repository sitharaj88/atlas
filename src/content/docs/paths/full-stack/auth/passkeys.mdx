## What a passkey is

A public-private keypair stored by the user's device (iCloud Keychain, Google Password Manager, 1Password, etc.). Private key never leaves the device. Server stores the public key only.

Login = device prompts user (Face ID, fingerprint), signs a challenge, sends signature back. Server verifies.

## Why it matters

- **Phishing-resistant** — keys are bound to your domain. A fake site can't trick the device into signing.
- **No password to leak.** Database breach exposes only public keys (useless to an attacker).
- **No reuse.** Each site has a unique keypair.

## Implementation

Use **`@simplewebauthn/server`** + **`@simplewebauthn/browser`**. Two flows:

1. **Register** — server generates a challenge, browser asks device to create a credential, server stores the credential's public key.
2. **Authenticate** — server generates a challenge, browser asks device to sign, server verifies.

A library is mandatory. WebAuthn has many edge cases.

## When to ship

- New apps — passkeys + OIDC + email-magic-link as fallbacks.
- Migration — add passkeys alongside passwords; let users opt in.
