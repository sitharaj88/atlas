## What WebRTC is

A browser API for **peer-to-peer** real-time media (audio, video) and data channels. The browsers exchange ICE candidates via your server, then talk directly to each other.

```ts
const pc = new RTCPeerConnection();
const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
stream.getTracks().forEach((t) => pc.addTrack(t, stream));
// Exchange offer/answer SDP and ICE candidates with the peer through YOUR signaling server.
```

## What you still need

- **Signaling server** — WebSocket/HTTP-based path for the two peers to find each other (offer, answer, ICE).
- **STUN/TURN** — when peers can't directly reach each other (behind NAT/firewall). TURN relays media; expensive.
- **SFU/MCU** — for multi-party calls, you usually proxy through a media server (LiveKit, Mediasoup, Janus).

## When pure WebRTC

- 1-to-1 calls (small project, controlled network).
- Latency-critical data channels.

## When use a media SaaS

- Group calls.
- Recording, transcription, moderation.
- Production reliability.
