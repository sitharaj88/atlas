## What's still true

- **Resources, not actions.** `POST /orders/123/cancel` is fine; better is `POST /orders/123/cancellations`.
- **Verbs match intent.** `GET` reads, `POST` creates, `PUT` replaces, `PATCH` updates, `DELETE` removes.
- **Idempotency.** `PUT` and `DELETE` should be repeatable safely. `POST` usually isn't (use idempotency keys for retries).
- **Status codes are part of the contract.** `200`, `201`, `204`, `400`, `401`, `403`, `404`, `409`, `422`, `429`, `500`. ([cheatsheet](/cheatsheets/http-status-codes/))
- **Pagination via `?cursor=` or `?page=`.** Cursor is friendlier for changing data.

## What's evolved

- **JSON every time.** XML is dead in REST.
- **Errors via RFC 7807 Problem Details.**
- **Versioning** via header (`Accept: application/vnd.atlas.v2+json`) or path (`/v2/...`). Pick one and stick.
- **Authentication** via Bearer tokens (JWT for stateless, opaque for sessions).

## What's outdated

- **HATEOAS** as a strict requirement. Most APIs don't follow links.
- **Heavy URI-versioning ceremony.** A version in the URL or header is enough.
- **OPTIONS for everything.** Just for CORS preflight.
