## What it is

```graphql
type User {
  id: ID!
  name: String!
  posts: [Post!]!
}
type Query {
  user(id: ID!): User
}
```

```graphql
query {
  user(id: "1") {
    name
    posts { title }
  }
}
```

Clients ask for exactly the fields they need. Server resolves the graph.

## Pros

- One endpoint. One round-trip per page.
- Strongly typed schema (introspection, codegen, IDE help).
- Efficient over slow networks (just the fields you need).

## Cons

- Caching is hard (no URLs to cache).
- N+1 query problem in resolvers (DataLoader is mandatory).
- More server complexity vs REST.
- Browser DevTools don't help as much.

## When GraphQL pays

- **Many client teams** querying the same data shape, all wanting different fields.
- **Mobile apps** on slow networks.
- Public APIs serving heterogeneous consumers.

## When REST is better

- Simple CRUD.
- Small team.
- Public read-heavy API where HTTP caching matters.
