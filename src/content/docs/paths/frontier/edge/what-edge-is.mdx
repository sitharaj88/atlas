## What it is

Traditional servers live in one or a few data centers. "Edge" means your code runs at hundreds of CDN nodes worldwide. A user in Tokyo hits Tokyo, not Virginia. Latency drops from 200ms to 20ms.

## The trade-offs

- **Latency** — wins for users not near your origin.
- **Runtime** — typically a Web-Standards subset of Node (no `fs`, no `child_process`, limited Node APIs).
- **Cold starts** — usually under 10ms (vs Lambda's hundreds).
- **State** — none, by default. Use a globally-distributed DB or KV (Cloudflare D1, Workers KV, Upstash, Turso).

## Mental model

Edge functions are **stateless request handlers**. Web standards in, Web standards out:

```ts
export default {
  async fetch(req: Request): Promise<Response> {
    return new Response('Hello from the edge');
  },
};
```

Same function, all platforms (Cloudflare Workers, Vercel Edge, Deno Deploy).

## When to pick edge

- Geo-distributed user base.
- Auth checks before forwarding.
- A/B testing at the edge.
- Light, latency-critical logic.

## When NOT

- Heavy compute (CPU limits per request).
- Long-running work (timeouts).
- Native-binary dependencies.
