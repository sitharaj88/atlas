## The problem

Two users edit the same document offline. They reconnect. Whose change wins? Last-writer-wins is OK for some data, terrible for others.

## CRDTs

Data structures designed so concurrent edits **always merge cleanly** — the order operations arrive doesn't matter. Two replicas applying the same set of ops end up identical, regardless of order.

## The intuition

Each operation has a unique ID (timestamp + author). Operations are commutative under the merge function. "User A inserted X at position 5" + "User B inserted Y at position 5" → both inserts coexist; ordering deterministic by ID.

## Real CRDT libraries

- **Yjs** — most popular for collaborative documents. Used in CodeMirror, ProseMirror, Tiptap.
- **Automerge** — JSON-document CRDTs. Strong type story.
- **Liveblocks** — managed CRDT service with React/Vue/Svelte hooks.

You almost never implement CRDTs by hand — pick a library.
