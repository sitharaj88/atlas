## What it is

A portable binary format that runs in the browser (and Node, Deno, Bun, edge runtimes). Compiled from C/C++/Rust/Zig/AssemblyScript. Runs in a sandboxed VM with no DOM access (talks to JS for that).

## What it's good at

- **CPU-heavy** work: image processing, codecs (FFmpeg.wasm), 3D, simulations, ML inference.
- **Porting native libraries** (OpenCV, SQLite) to the web.
- **Polyfills for low-level features** (e.g., `wasi-fs` for file system in browser).

## What it's NOT

- **A JS replacement.** Calling DOM APIs requires JS bridge — same overhead as before.
- **Magically faster.** For typical web logic (calling fetch, manipulating arrays), modern V8 beats unoptimized Wasm.

## Use it when

The bottleneck is genuine compute, not network or DOM. Otherwise, plain JS wins on dev cost.
