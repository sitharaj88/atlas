## Hydration recap

Server renders HTML → ships JS → client re-runs every component to "hydrate" event listeners. The bigger your app, the more JS, the slower hydration.

## Resumability

Server renders HTML AND serializes the application state (event handlers, closures). Client never "hydrates" — it lazy-loads the bits of code needed only when an event fires.

```text
Click button → load just the click handler chunk → run it
```

The result: time-to-interactive doesn't grow with app size.

## Trade-offs

Pros: lightning-fast TTI even on huge apps; the bigger the app, the bigger the win.

Cons: smaller ecosystem, smaller team familiarity, lots of tiny chunks (HTTP/2 helps).
