> **What you'll learn.** A short tour of CSS Color 4 — the functions and color spaces that have arrived in every modern browser.

## oklch — perceptually uniform

```css
:root { --brand: oklch(72% 0.18 70); }   /* lightness, chroma, hue */
```

Three components:

- **L** (0–100%) — perceived lightness. Two colors with the same L *look* equally bright.
- **C** (0–~0.4) — chroma (saturation). Higher = more vivid.
- **H** (0–360deg) — hue.

Why prefer oklch over hsl? In hsl, the same L can look very different across hues (yellow-green at 50% looks brighter than blue at 50%). Oklch matches your eye.

## color-mix

```css
.btn:hover { background: color-mix(in oklch, var(--brand), white 20%); }
```

Mix two colors in a chosen color space. Great for hover states, subtle tints, theme variants:

```css
:root {
  --brand: oklch(72% 0.18 70);
  --brand-soft: color-mix(in oklch, var(--brand), white 80%);
  --brand-strong: color-mix(in oklch, var(--brand), black 20%);
}
```

## P3 — wider colors on modern screens

Standard sRGB is what we've used since 2000. Modern displays cover a larger gamut: P3, Rec2020. CSS lets you opt in:

```css
.vibrant { color: color(display-p3 1 0 0.5); }
```

The browser uses P3 on capable displays and falls back gracefully. Saturated colors look more saturated.

## Color contrast still matters

Wider gamut doesn't change accessibility. Pair with:

```css
.btn { background: var(--brand); color: oklch(98% 0 0); }   /* near-white text */
```

The `oklch(98% 0 0)` is "very light, no chroma" — predictable contrast.

<Callout variant="tip" title="Migrate gradually">
You don\'t have to switch all colors to oklch. Use it where you\'re computing or theming, where uniformity helps. Hex still works fine for fixed brand colors.
</Callout>
