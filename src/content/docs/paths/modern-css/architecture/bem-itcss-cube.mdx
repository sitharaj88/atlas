> **What you'll learn.** Three methodologies you'll meet in legacy code (and idea-mining for new code).

## BEM — Block, Element, Modifier

```css
.card { /* block */ }
.card__title { /* element of block */ }
.card--featured { /* modifier on block */ }
.card__title--large { /* modifier on element */ }
```

Long, ugly, but unambiguous. BEM solves naming collisions through convention. CSS Modules and Tailwind both eliminate the need.

## ITCSS — Inverted Triangle CSS

Layer your CSS by specificity:

```text
1. Settings    — variables
2. Tools       — mixins, functions
3. Generic     — resets, normalize
4. Elements    — bare HTML elements (h1, a)
5. Objects     — design patterns (.media, .stack)
6. Components  — UI components (.card, .btn)
7. Utilities   — overrides, !important if needed
```

Specificity grows as you go down. `@layer` (modern) is the spiritual successor.

## CUBE — Composition Utility Block Exception

Andy Bell's modern methodology. Compose from utilities (axioms), then build blocks, then handle exceptions. Pairs well with `@layer`.

## What to take from each

- **BEM** — explicit naming when scoping isn't an option.
- **ITCSS** — order CSS by specificity. Now: use `@layer`.
- **CUBE** — small, composable axioms before bespoke blocks.

<Callout variant="tip" title="Don't pick a methodology, pick the principles">
The valuable part is the philosophy: scope, order, layered specificity. Modern CSS (layers, modules, container queries) lets you apply the principles without buying the entire methodology.
</Callout>
