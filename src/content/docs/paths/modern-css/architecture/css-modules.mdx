> **What you'll learn.** A way to scope CSS automatically — your `.btn` is unique to this file, no global pollution.

## The setup

```css
/* button.module.css */
.btn { padding: 0.6rem 1rem; border-radius: 8px; }
.btn:hover { background: navy; }
```

```jsx
// button.jsx
import s from './button.module.css';
export function Button(props) {
  return <button className={s.btn}>{props.children}</button>;
}
```

The bundler turns `.btn` into something like `.button_btn__a1b2c3`. Two components can both have a `.btn` and they don't collide.

## Composes

Reuse a class from another file:

```css
.primary {
  composes: btn from './base.module.css';
  background: var(--brand);
}
```

`composes` is CSS Modules-specific syntax (not standard CSS). The runtime joins the class lists.

## When CSS Modules wins

- You like writing CSS, not utility soup.
- Your team prefers strict scoping.
- You want a file per component, no global side effects.

## When it loses

- You want one global utility-first system (use Tailwind).
- You want types on your styles (use Vanilla Extract).
- You don't have a bundler (use plain CSS or Lightning CSS).

<Callout variant="tip" title="Pair with semantic CSS">
CSS Modules let you write component CSS without naming-collision anxiety. Combine with the cascade-layer pattern: scoped components in a `components` layer, utilities later.
</Callout>
