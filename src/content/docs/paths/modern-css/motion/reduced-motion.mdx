> **What you'll learn.** Motion-triggered nausea is real; ~30% of vestibular-disorder sufferers report it. The fix is two lines.

## The blanket reset

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Drop into your reset. Every animation now becomes near-instant.

## The targeted approach

The blanket version makes UI snappy but can lose useful affordances (a checkbox checking, a focus ring sliding). Better: opt in per-component.

```css
.menu { transition: transform 200ms; }

@media (prefers-reduced-motion: reduce) {
  .menu { transition: none; }
}
```

For animations users *want* (checkbox checks, progress indicators), keep them brief and essential.

## In JavaScript

```js
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduce) playIntroAnimation();
```

Listen for changes:

```js
matchMedia('(prefers-reduced-motion: reduce)')
  .addEventListener('change', e => updateMotion(e.matches));
```

## What "reduce" means

Not "no motion." It means "no large or unnecessary motion." Subtle fades and brief affordances are fine. Big parallax, autoplay video, animated backgrounds — those are out.

<Callout variant="tip" title="Default to reduced motion in design">
If your design only feels right with heavy motion, it\'s probably over-designed. The reduced version should still feel polished. Build that first; add motion as enhancement.
</Callout>
