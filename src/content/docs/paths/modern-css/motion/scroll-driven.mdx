> **What you'll learn.** Two CSS-only patterns that replace whole IntersectionObserver scripts.

## Scroll progress bar

```css
@keyframes fill { to { transform: scaleX(1); } }

.progress {
  position: fixed; top: 0; left: 0; right: 0; height: 3px;
  transform: scaleX(0); transform-origin: 0 0;
  background: var(--brand);
  animation: fill linear;
  animation-timeline: scroll(root);
}
```

The bar fills as the user scrolls the page. No JS.

## Fade in when in view

```css
.card {
  opacity: 0;
  transform: translateY(2rem);
  animation: rise linear both;
  animation-timeline: view();
  animation-range: entry 10% cover 30%;
}
@keyframes rise { to { opacity: 1; transform: none; } }
```

Each `.card` animates as it enters the viewport. `animation-range` tunes when the animation starts and ends.

## Browser support

Cutting-edge as of 2026. Chromium first, Safari/Firefox shipping. Wrap in `@supports`:

```css
@supports (animation-timeline: scroll()) {
  /* scroll-driven version */
}
```

Without support, the static styles still apply — degrade gracefully.

<Callout variant="warn" title="Respect reduced-motion">
Pair scroll-driven animations with `@media (prefers-reduced-motion: reduce)` to disable. Heavy scroll-bound parallax is a top motion-sickness trigger.
</Callout>
