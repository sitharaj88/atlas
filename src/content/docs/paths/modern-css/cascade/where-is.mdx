> **What you'll learn.** Two pseudo-classes that let you write less, fight specificity less, and read CSS more easily.

## `:is()` — group selectors

```css
/* Without :is() — repetition */
header h1, header h2, header h3,
main h1, main h2, main h3,
footer h1, footer h2, footer h3 { font-family: serif; }

/* With :is() */
:is(header, main, footer) :is(h1, h2, h3) { font-family: serif; }
```

Specificity: `:is(...)` takes the **highest specificity of its arguments**. So `:is(.foo, #bar)` is `0,1,0,0` (the ID).

## `:where()` — same grouping, zero specificity

```css
:where(header, main, footer) h1 { font-family: serif; }
```

Identical to `:is(...)` but always 0,0,0 specificity. Perfect for resets and base styles you don't want to fight later:

```css
:where(button, [type='button']) {
  /* base button styles — easy to override */
}
```

## `:not()` — exclusion

```css
button:not(:disabled, .ghost) { background: navy; }
```

`:not()` accepts a selector list (multiple args). Specificity equals its **most specific argument** (just like `:is`).

## Combine for clean rules

```css
:where(article) :is(h2, h3) + :is(p, ul) {
  margin-block-start: 0.4em;
}
```

Translation: in any `article`, paragraphs/lists immediately after `h2`/`h3` get tighter top margin. Reads almost as plain English.

## When to use which

- **`:is()`** — when you want shorter selectors AND want them to keep their full specificity (you're competing with other rules).
- **`:where()`** — for base styles, resets, or whenever you want overrides to be easy.
- **`:not()`** — exclude. Pairs cleanly with `:is()`.

<Callout variant="tip" title="Default to `:where` for resets">
Anything that says "this is the baseline" — typography, button defaults, link styles — wrap selectors in `:where()`. Page-specific styles override without needing more specificity.
</Callout>
