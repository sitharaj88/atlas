## Both work

```ts
interface User { id: number; name: string; }
type    User = { id: number; name: string; };
```

Either is fine for object shapes. Pick consistently.

## Real differences

| Feature | `interface` | `type` |
|---|---|---|
| Object shapes | ✓ | ✓ |
| Unions / intersections | ✗ | ✓ |
| Computed types (mapped, conditional, template literal) | ✗ | ✓ |
| Declaration merging (multiple declarations combine) | ✓ | ✗ |
| Extending | `extends` | `&` |

## Use `interface` for…

- Public API of a library (declaration merging is helpful for users to augment).
- Class-like shapes that may be extended.

## Use `type` for…

- Unions, intersections, or anything computed.
- Tuples, function signatures, conditionals, mapped types.

## A common pattern

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
//   ^ must be `type` — interfaces can't be unions
```

When in doubt, `type` is more powerful; `interface` is more declarative. Many codebases use only `type` for simplicity.
