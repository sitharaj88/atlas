## Primitives

```ts
let n: number;
let s: string;
let b: boolean;
let big: bigint;
let sym: symbol;
let nul: null;
let und: undefined;
```

## Literal types

A type with exactly one possible value:

```ts
let role: 'admin' | 'user' | 'guest' = 'user';
let port: 80 | 443 = 443;
```

`'admin'` is both a value and a type — a value of type `'admin'`. Unions of literals make finite-state types.

## Unions

```ts
type ID = string | number;
function find(id: ID) { /* ... */ }

// Discriminated union — one common literal field
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
```

Discriminated unions are the workhorse pattern. Branch on the literal:

```ts
function handle<T>(r: Result<T>) {
  if (r.ok) return r.value;
  else return r.error;
}
```

## Intersections

Combine types:

```ts
type Named = { name: string };
type Aged  = { age: number };
type Person = Named & Aged;     // { name: string; age: number }
```

`&` is "AND" (must satisfy both); `|` is "OR" (satisfies either).

## Const assertions

```ts
const dirs = ['n', 's', 'e', 'w'] as const;
type Dir = typeof dirs[number]; // 'n' | 's' | 'e' | 'w'
```

`as const` deeply freezes literals into their narrowest types. The cleanest way to get a union from a list.

<Callout variant="tip" title="Discriminated unions over enums">
Most teams now prefer discriminated unions over `enum`. Better tree-shaking, cleaner type narrowing, no runtime cost.
</Callout>
