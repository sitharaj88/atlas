## Typing functions

```ts
function add(a: number, b: number): number { return a + b; }
const add: (a: number, b: number) => number = (a, b) => a + b;

type Add = (a: number, b: number) => number;
const add: Add = (a, b) => a + b;
```

Three equivalent ways. Use the type alias when the same signature appears in multiple places.

## Optional and default params

```ts
function greet(name: string, loud = false) {
  return loud ? `HI ${name}` : `hi ${name}`;
}
function visit(url: string, query?: Record<string, string>) {}
```

`loud = false` infers `boolean`. `query?` is `Record<string, string> | undefined`.

## Rest parameters

```ts
function sum(...nums: number[]) { return nums.reduce((a,b)=>a+b, 0); }
function logAll(prefix: string, ...rest: unknown[]) {}
```

## Overloads — rare and explicit

For functions whose return type depends on input type:

```ts
function parse(input: string): string[];
function parse(input: number): number[];
function parse(input: string | number): unknown[] {
  // implementation
  return [];
}

parse('a,b,c'); // string[]
parse(42);      // number[]
```

Three signatures: two overloads + one implementation. Callers see only the overloads.

**Often a generic is cleaner:**

```ts
function first<T>(arr: T[]): T | undefined { return arr[0]; }
```

Reach for overloads only when generics can't express the relationship.

## Function type compatibility

A function with **fewer parameters** is assignable to one expecting more (you can always ignore extras):

```ts
const handlers: ((x: number, y: number) => void)[] = [];
handlers.push((x) => console.log(x));    // ✓ ignores y
```

This is why `arr.map((x) => x*2)` works — `map` provides `(item, index, array)` but you only declare `item`.
