## Project references

Split a tsconfig into composable pieces:

```json
// tsconfig.base.json — shared compiler options
{ "compilerOptions": { "strict": true, "target": "ES2022", "composite": true } }

// packages/core/tsconfig.json
{ "extends": "../../tsconfig.base.json", "include": ["src"], "compilerOptions": { "outDir": "dist" } }

// packages/app/tsconfig.json
{
  "extends": "../../tsconfig.base.json",
  "include": ["src"],
  "references": [{ "path": "../core" }]
}
```

`composite: true` enables incremental builds. `tsc --build` walks the references and builds in order.

## Path aliases

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "~/*": ["src/*"],
      "@core/*": ["packages/core/src/*"]
    }
  }
}
```

```ts
import { foo } from '~/lib/foo';
import { Bar } from '@core/bar';
```

Mirror the same aliases in your bundler config (Vite: `resolve.alias`).

## Workspace tools

- **pnpm workspaces** — most common. `pnpm-workspace.yaml` lists packages.
- **Turborepo** — task orchestration on top of workspaces.
- **Nx** — opinionated monorepo platform.

For TS-only setups, pnpm workspaces + project references covers most teams.
