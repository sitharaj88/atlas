## Two viable strategies

**1. allowJs + checkJs** — keep `.js` files, type-check them.

```json
{ "compilerOptions": { "allowJs": true, "checkJs": true, "strict": false } }
```

Adopt strict mode flags one at a time. Convert files to `.ts` as you touch them.

**2. JSDoc types in JS** — never convert files; just add types as comments.

```js
/** @typedef {{ id: string; name: string }} User */

/** @param {User} user */
function greet(user) {
  return `Hello, ${user.name}`;
}
```

Works in `.js` files with `checkJs: true`. Suite of teams (Bun internals, Svelte's runtime) use this.

## Recommended order

1. **Start in a corner** — pick a small module. Add TS, fix errors.
2. **Add `tsconfig.json`** with `allowJs: true, checkJs: false, strict: false`.
3. **Convert leaf files first** — files no other file imports are easiest.
4. **Turn on flags incrementally**: `noImplicitAny` → `strictNullChecks` → `strict`.
5. **`@ts-expect-error` to mark known issues** with TODO so they don't drift.

## Tools that help

- **`type-coverage`** — % of typed lines.
- **`ts-migrate`** (Airbnb) — automated codemod.
- **DefinitelyTyped** — for libraries without types.

## Don't

- **Big-bang rewrite.** Months of pain, no business value.
- **Skip `strict`.** "I'll turn it on later" rarely happens. Better strict-on-leaf than loose-everywhere.
- **Use `any` to silence errors.** Use `unknown` and narrow.
