## Shared schema is the goal

When client and server speak via HTTP, the type contract is what's left if you delete the runtime code. Best results come from a single source of truth shared by both:

- **Zod schemas** — `z.infer<typeof X>` extracts the type.
- **tRPC** — types travel directly with router code; no schema layer.
- **OpenAPI** — generate types from a spec.

```ts
// shared/user.ts
import { z } from 'zod';
export const UserSchema = z.object({
  id: z.string(),
  email: z.string().email(),
});
export type User = z.infer<typeof UserSchema>;

// server (Hono)
app.get('/users/:id', (c) => c.json(getUser(c.req.param('id'))));

// client
const data = UserSchema.parse(await fetch(`/users/${id}`).then(r => r.json()));
//    ^ User
```

Same schema, both ends. Validation + types in one.

## Typed event emitters

```ts
type Events = {
  login:  { userId: string };
  logout: void;
  error:  { code: number; message: string };
};

type Emitter<E extends Record<string, any>> = {
  on<K extends keyof E>(name: K, fn: (payload: E[K]) => void): void;
  emit<K extends keyof E>(name: K, payload: E[K]): void;
};

const e: Emitter<Events> = create();
e.on('login', ({ userId }) => /* ... */);
e.emit('error', { code: 500, message: 'oops' });
```

Strongly-typed pub/sub with no runtime overhead.

## Branded IDs

```ts
type UserId = string & { __brand: 'UserId' };
type PostId = string & { __brand: 'PostId' };

function getUser(id: UserId) {}
const x = 'abc' as UserId;
const y = 'abc' as PostId;
getUser(x); // ✓
getUser(y); // ✗
```

Prevents string-ID swaps at compile time.
