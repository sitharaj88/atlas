## The pattern

```ts
type Result<T> =
  | { status: 'pending' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

function handle<T>(r: Result<T>) {
  switch (r.status) {
    case 'pending': return 'Loading…';
    case 'success': return r.data;     // ✓ `data` is in scope
    case 'error':   return r.message;  // ✓ `message` is in scope
  }
}
```

The shared **`status`** field discriminates. TypeScript narrows automatically inside each branch.

## Exhaustive checks

```ts
function handle<T>(r: Result<T>) {
  switch (r.status) {
    case 'pending': return 'Loading…';
    case 'success': return r.data;
    case 'error':   return r.message;
    default: {
      const _: never = r;          // ← compile error if a new variant is added
      return _;
    }
  }
}
```

Add a new `Result` variant → the `default` errors → you must handle it. The compiler enforces completeness.

## When to use

- **State machines** — pending/loading/success/error.
- **Variant data** — different shapes for different kinds of items.
- **Event types** — `{ type: 'click'; x: number; y: number } | { type: 'scroll'; delta: number }`.
