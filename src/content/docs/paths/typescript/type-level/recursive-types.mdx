## A simple recursion

```ts
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
```

Walks every property; if it's an object, recurse; otherwise leave alone.

## Guardrails

TypeScript caps recursion depth (~100 for most cases, 1000 with `tail-recursive` patterns). For deeply nested types, structure as **tail-recursive** when possible:

```ts
type Reverse<L extends unknown[], A extends unknown[] = []> =
  L extends [infer H, ...infer T] ? Reverse<T, [H, ...A]> : A;

type R = Reverse<[1, 2, 3]>; // [3, 2, 1]
```

Accumulator pattern → tail recursion → bigger inputs work.

## Common uses

- **`Awaited<T>`** — unwrap nested promises.
- **`DeepPartial<T>`** — make every nested field optional.
- **JSON / form schema types** — recursive shape definitions.

## When NOT to recurse

If your type compiles slowly, IDE feels sluggish, or you hit "Type instantiation is excessively deep" — back off. Sometimes a non-generic explicit shape is more readable AND faster.

<Callout variant="warn" title="Type-level recursion is fun and addictive">
Resist the temptation to type-level-program everything. The point of types is to help maintainers. Clever recursive types that nobody on the team understands hurt more than they help.
</Callout>
